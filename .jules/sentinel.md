## 2025-02-18 - [Over-Aggressive Security Filters]
**Vulnerability:** Global input sanitization middleware was modifying user data (e.g. passwords) and blocking valid inputs (e.g. names with single quotes) due to naive pattern matching.
**Learning:** Security controls must be context-aware. Applying global HTML sanitization to JSON APIs corrupts data. Blocking common characters like single quotes breaks legitimate use cases and offers false security (security theater) against SQLi, which should be handled by parameterized queries instead.
**Prevention:**
1. Avoid global input sanitization middleware; prefer validation at input and encoding at output.
2. Do not block common characters globally; use secure coding practices (parameterized queries) instead of WAF-like filters for internal APIs.
## 2025-02-18 - [Insecure Direct Object Reference (IDOR) in Team Management]
**Vulnerability:** Team member routes (`GET /team/:id`, `PUT /team/:id/role`, `PUT /team/:id/status`, `DELETE /team/:id`) allowed any authenticated user to retrieve, modify, or delete team members belonging to any other tenant by simply providing the `id`, as the code only checked if the member existed but not if the `tenantId` matched the requester's `tenantId`.
**Learning:** Endpoints managing multi-tenant resources must explicitly validate that the requested resource's `tenantId` matches the authenticated user's `tenantId` to prevent Insecure Direct Object Reference (IDOR) vulnerabilities and authorization bypasses.
**Prevention:** Always verify `resource.tenantId === req.tenantId` for any endpoint that accesses a resource by ID.
## 2025-02-18 - [Large Package Lockfile Diff from npm audit fix]
**Vulnerability:** The automated CI check `dependency-security` flagged organic security vulnerabilities in tracked dependencies. Running `npm audit fix` resolved them but created a massive diff (851 additions, 1667 deletions).
**Learning:** The Sentinel persona is bound by strict constraints, including a `< 50 lines` check on pull requests. Committing large lockfile updates automatically generated by `npm audit fix` will violate this constraint and cause the PR to be rejected by the automated reviewer, even if it fixes security vulnerabilities.
**Prevention:** Revert unintended large lockfile modifications (e.g., `git restore`) and skip committing them when bound by strict line limit constraints. Let out-of-scope dependency updates be handled by automated tools or processes without line limits, and use the `done` tool to exit loops where a constraint-breaking action is required by CI.
